# 2-Tier Web Application CI/CD Pipeline

A simple, complete CI/CD setup running a two-tier web application on a single AWS EC2 instance. Jenkins handles continuous integration directly on the host, building the application container, running tests, pushing to Amazon ECR, and executing deployments upon code pushes to GitHub.

Fundamentally, this is a URL shortener application hosted on a t3.large instance that has Jenkins and Docker installed on the root volume alongside a containerized MySQL database.

The core goal of this project was to understand what a tech stack is and how it operates.

## Tech Stack

| Tool | Role in Project |
|---|---|
| **Flask** | The web application backend (URL shortener). Kept minimal to focus on pipeline mechanics. |
| **MySQL 8.0** | Runs as a Compose service using the official Docker image with a persistent named volume. |
| **Docker & Compose** | Manages the local two-service stack (`compose.yaml`). Web builds via Dockerfile; DB pulls official MySQL image. |
| **Jenkins** | Self-hosted on the host instance. Runs a declarative `Jenkinsfile` triggered by GitHub webhooks. |
| **Amazon ECR** | Private AWS image registry holding tagged production builds. |
| **AWS EC2 / IAM** | Single t3.large instance using an IAM Instance Profile for seamless ECR authentication without static access keys. |

## Key Architecture Concepts

### State & Persistence

MySQL's data survives every redeploy because it lives in a Docker named volume mounted on the host:

```yaml
volumes:
  - mysql-data:/var/lib/mysql
```

Amazon ECR holds the built web application images. The MySQL data persists strictly on the EC2 instance inside the Docker named volume and never leaves it. ECR acts as the image registry, not application data storage.

### Core Files

Everything comes down to three primary files:

- **`Dockerfile`** — Builds the Flask application image.
- **`compose.yaml`** — Wires Flask to MySQL with health-gated startup and a named volume for data persistence.
- **`Jenkinsfile`** — Defines the 5-stage pipeline (Checkout, Build, Test, Push, Deploy) that connects GitHub to ECR and updates the running instance.

### Credential & Security Model

No secrets or hardcoded access keys are committed to the repository.

- **Database Secrets:** `compose.yaml` reads `${DB_NAME}`, `${DB_USER}`, `${DB_PASSWORD}`, and `${DB_ROOT_PASSWORD}` from a local, gitignored `.env` file (see `.env.example` for required shape). The application connects as a restricted non-root MySQL user.
- **AWS Authentication:** Jenkins authenticates to ECR via the EC2 Instance Profile using temporary tokens generated by `aws ecr get-login-password`. No static AWS access or secret keys are saved on disk.

## Setup & Execution Order

To build or recreate this environment from scratch:

**1. Provision EC2 Instance**

- Launch a t3.large instance running Amazon Linux 2023.
- Attach an IAM role (Instance Profile) with ECR push/pull permissions (`AmazonEC2ContainerRegistryPowerUser`).
- Configure the Security Group to allow inbound traffic on ports 8080 (Jenkins), 5000 (Flask App), and 22 (SSH).

**2. Install Dependencies**

- On the instance, install Docker, Docker Compose, AWS CLI, and Jenkins.
- Start and enable both Docker and Jenkins services:

```bash
sudo systemctl enable --now docker jenkins
sudo usermod -aG docker jenkins
sudo systemctl restart jenkins
```

> Restarting Jenkins after adding it to the `docker` group ensures permission updates take effect.

**3. Local Container Verification**

- Copy `.env.example` to `.env` and fill in database credentials.
- Run `docker compose up -d` to verify Flask and MySQL start up properly.
- The app service utilizes a MySQL healthcheck block to ensure the database is fully accepting connections before starting the Flask web server.

**4. Configure Jenkins & GitHub**

- Store your GitHub Personal Access Token (PAT) inside Jenkins credentials.
- Create a Pipeline job pointing to your GitHub repository.
- Add a Webhook in GitHub pointing to `http://<EC2-PUBLIC-IP>:8080/github-webhook/` to trigger automated builds on every push.

**5. ECR Integration & Deployment**

- Ensure your `Jenkinsfile` on your instance runs `aws ecr get-login-password` to authenticate against ECR before running `docker compose up -d` and `docker compose down`.
